### Font: the Pacifico subtitle never loaded at all

Comparing the v6 render against v5 pixel by pixel revealed that in v5, the subtitle "where the sun never sets" rendered in a serif fallback font, not Pacifico — plain to see when zoomed in: upright serif letters, not script. Root cause: no DOM element ever used Pacifico, so the browser never loaded that face; `document.fonts.ready` resolved before the face was requested, while the `?shot=` scene only draws once — there is no second repaint that could fix it. In the normal editor this bug heals itself through the next repaint; in a screenshot it does not.

The same behaviour once made ONE square v6 render draw the Anton title in fallback (the title shrank about 15%, pixel diff 12.74) — flaky, gone on re-run. Same root cause: fonts.ready alone is not enough.

The fix (`app/src/shots.js` + `app/src/main.js`): before drawing anything, explicitly load `document.fonts.load('100px Anton')` and `document.fonts.load('40px Pacifico')` — in runCoverScene, runEditorScene, and the editor bootstrap. After the fix, rendering became deterministic (3× square re-runs: diff 0.12 vs baseline) and the subtitle is finally real Pacifico script — matching the design ("neon script subtitle") and closer to the top entries, which also use script.

Visual impact vs v5: only the subtitle (Pacifico script instead of serif fallback). Title, panels, grade, furniture: pixel-identical to v5 (downscale-8× diff around 0.03–0.04 before the font fix; after the fix, the only remaining diff sits in the subtitle line itself).
